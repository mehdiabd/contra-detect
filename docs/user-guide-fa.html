راهنمای کوتاه کار با سامانه تشخیص تناقض

برای کاربران و تحویل‌گیرندگان فنی · مطابق نسخهٔ 1.1.2 · به‌روزرسانی راهنما در ۱۲ آبان ۱۴۰۵

سامانه متن پست‌های یک کاربر در یک بستر را مقایسه می‌کند و وجود تناقض، جفت پست‌های متناقض و یک نشان‌گر عددی برمی‌گرداند. بسترهای ورودی ایکس، تلگرام و اینستاگرام هستند؛ ورودی تحلیل، متن است.

۱. پشت سامانه چه می‌گذرد

  1. دریافت: پست‌ها از منبع سازمان یا فیلد posts در درخواست خوانده و با کاربر، بستر و تاریخ فیلتر می‌شوند.
  2. انتخاب جفت: پس از پاک‌سازی برای انتخاب متن‌های هم‌موضوع، حداکثر ۸۰ جفت هر کاربر با شباهت واژگانی انتخاب می‌شود؛ همهٔ تاریخچه الزاماً بررسی نمی‌شود.
  3. پیش‌بینی: سه مدل رابطهٔ معنایی هر جفت را تأییدکننده، متناقض یا خنثی تشخیص می‌دهند. دو مدل فارسی هرکدام وزن ۲۵٪ و مدل چندزبانه وزن ۵۰٪ دارند.
  4. تجمیع: آستانهٔ تناقض جفت ۰٫۵۵ و آستانهٔ نشان‌گر کاربر ۰٫۵۰ است. اگر جفت قابل بررسی وجود نداشته باشد، نتیجه «دادهٔ ناکافی» است.

۲. درخواست بفرستید و نتیجه بگیرید

  1. مستندات تعاملی سامانه را باز کنید و یکی از سه مسیر زیر را انتخاب کنید. روش هر سه POST و بدنهٔ درخواست آن‌ها یکسان است.
  2. روی Try it out بزنید، بدنهٔ نمونه را جایگزین کنید و Execute را بزنید. نتیجه در بخش Server response دیده می‌شود.
نتیجهٔ مورد نیازمسیر درخواست
تشخیص وجود تناقض/api/v1/users/contradiction
دریافت جفت پست‌ها به‌عنوان شاهد/api/v1/users/contradictory-posts
دریافت نشان‌گر عددی/api/v1/users/contradiction-score

برای دادهٔ سازمان: نام کاربری واقعیِ موجود در منبع را جایگزین example_user کنید؛ آدرس کامل پروفایل ننویسید. در platform_name یکی از مقادیر twitter، telegram یا instagram را بگذارید. تاریخ‌ها میلادی‌اند و ابتدا و انتهای بازه را شامل می‌شوند؛ حذف date_range مجاز است.

{
  "user_ids": ["example_user"],
  "platform_name": "twitter",
  "date_range": {
    "start_date": "2026-10-01",
    "end_date": "2026-10-20"
  }
}

برای خواندن از منبع سازمان، فیلد posts را کاملاً حذف کنید؛ مقدار posts: [] یعنی خودتان دادهٔ خالی فرستاده‌اید. چند شناسه در user_ids جداگانه تحلیل می‌شوند. فهرست خالی، حالت برترین‌هاست؛ با منبع سازمان، حداکثر ۱۰ نتیجه از میان حداکثر ۳۰ کاربر نامزد برمی‌گردد.

نمونهٔ آماده برای آزمایش با دو متن دلخواه

این بدنه را در مسیر تشخیص وارد کنید؛ دریافت داده از منبع سازمان لازم نیست. برای استفاده از بازهٔ تاریخ در این حالت، زمان timestamp را هم برای پست‌ها بفرستید.

{
  "user_ids": ["guide_user"],
  "platform_name": "twitter",
  "posts": [
    {
      "user_id": "guide_user",
      "post_id": "a",
      "text": "من همیشه از تولید داخلی حمایت می‌کنم و خرید کالای ایرانی را ترجیح می‌دهم."
    },
    {
      "user_id": "guide_user",
      "post_id": "b",
      "text": "من هرگز از تولید داخلی حمایت نمی‌کنم و خرید کالای ایرانی را قبول ندارم."
    }
  ]
}

پاسخ این نمونه وضعیت completed، تصمیم true و یک جفت بررسی‌شده دارد.

۳. خروجی را درست بخوانید

در پاسخ موفق، فهرست results را بخوانید. اول وضعیت analysis_status را ببینید، سپس تصمیم has_contradiction و امتیاز score را تفسیر کنید.

نشانهٔ پاسخمعنی و اقدام
وضعیت completed و تصمیم trueدر جفت‌های بررسی‌شده تناقض پیدا شده است؛ برای گزارش، شواهد را از مسیر استخراج بگیرید.
وضعیت completed و تصمیم falseدر جفت‌های بررسی‌شده تناقضی مطابق آستانه پیدا نشده است.
وضعیت insufficient_dataجفت قابل بررسی وجود ندارد؛ تصمیم و امتیاز مربوط null هستند. تعداد پست‌ها، شناسه و بازهٔ تاریخ را بررسی کنید.
خطای ۵۰۳ با کد data_source_unavailableدریافت منبع خراب یا ناقص بوده؛ نتیجهٔ تحلیل وجود ندارد. اتصال و منبع داده را با پشتیبان بررسی کنید.
خطای ۵۰۳ با کد analysis_failedپردازش کامل نشده است؛ درخواست را به پشتیبان فنی گزارش کنید.
خطای ۴۲۲ورودی نامعتبر است؛ بستر، قالب تاریخ یا ترتیب شروع و پایان را اصلاح کنید.

فیلد post_count تعداد پست‌های پس از فیلتر و pair_count تعداد جفت‌های بررسی‌شده است. در شواهد، post_a و post_b متن، شناسه، بستر و زمان هر پست را دارند؛ contradiction_score امتیاز تناقض جفت و similarity شباهت واژگانی آن است.

نشان‌گر score بین صفر و یک است: میانگین امتیاز جفت‌های با امتیاز حداقل ۰٫۵۵؛ اگر چنین جفتی نباشد، یک‌چهارم بیشترین امتیاز برمی‌گردد. این نشان‌گر، احتمال قطعی تناقض فرد نیست. دقت ثبت‌شدهٔ ۸۶٫۹۶٪ مربوط به طبقه‌بندی جفت‌های آمادهٔ فارس‌تیل است؛ عملکرد کاربران واقعی باید روی دادهٔ سازمان سنجیده شود. بازخورد ارزیاب اول موقت است و نمونهٔ مثبت انسانیِ تأییدشده ندارد.

۴. راه‌اندازی و تحویل فنی

برای نصب تازه، دسترسی مخزن، ابزار دریافت فایل‌های بزرگ گیت و داکر لازم است. فایل .env را با الگوی .env.example و تنظیمات تحویلی مسئول زیرساخت آماده کنید؛ برای دادهٔ سازمان، ES_ENABLED=true باشد. سپس در پوشهٔ پروژه اجرا کنید:

git lfs install
git lfs pull
docker compose up -d --build

برای اجرای سامانه، وزن‌های نهایی موجود استفاده می‌شوند و آموزش دوباره لازم نیست. در نصب محلی، مستندات در http://localhost:8000/docs قرار دارند. پس از مرج و بیلد این به‌روزرسانی، وضعیت سلامت سرور باید مدل farstail-human-feedback-20261103-v1، سه عضو و مقدار model.release.verified=true را نشان دهد؛ کنترل هش مدل هنگام ساخت و شروع سرویس انجام می‌شود.

برای مشاهدهٔ خطاهای اجرا، دستور docker compose logs --tail=100 api را اجرا کنید. در تحویل، نسخهٔ کد، تنظیمات منبع، دسترسی فایل‌های مدل و یک نمونه درخواست و پاسخ موفق را ثبت کنید.

این راهنما مستقل است و بدون نصب ابزار اضافی در مرورگر باز می‌شود؛ برای نگهداری یا چاپ، از گزینهٔ چاپ مرورگر استفاده کنید.
